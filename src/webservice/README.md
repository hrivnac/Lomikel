# FinkBrowser workspace preview

This opt-in iteration refines the workspace shell, the header and panel 02 without changing the backend logic of the panels. The existing root `index.jsp` remains the default welcome page. The new shell is available at `/FinkBrowser/webservice/index.jsp` after `ant war`; use `?profile=null` to inspect it without an automatic graph query, or the same configured profile query string used by the existing UI. Do not run a configured profile against production merely to test layout.

Build from `ant/` with `ant war` using the usual local Ant properties and dependencies. `ant start-FinkBrowser` serves the resulting `lib/FinkBrowser.war` at the configured port, but starts a service that may connect to the configured backends. `ant war` does not deploy it; neither the `deploy*` targets nor a remote server are needed to preview the shell. For an isolated local test, run Jetty Runner bound to `127.0.0.1` on a spare port using the built WAR.

The new JSP is packaged under `webservice/`, but its `<base>` points at the WAR root so existing JS, CSS, detail fragments and relative action URLs remain unchanged. It statically includes the Fink `Init.jsp`. Panel 01's information and Reset workspace control are now in the top header: the `LomikelOverlap.png` icon sits beside a linked application name, and Version opens a light dialog containing the build metadata. The header keeps `id="mini"` for the existing graph initialization contract; the preview-only `TopMini.jsp` is no longer loaded or packaged. Panels 02 and 05 start at roughly half their former height and remain resizable and scrollable. Panel 02 still loads preview-only `webservice/Top.jsp`, preserving the original server/graph/command controls, action IDs, Gremlin callbacks and dynamic `#commands` target; its initial command is substituted by the WAR build. The legacy pages remain unchanged. Other panels still load their root fragments. The w2ui layout names (`layout`, `layoutLeft`, `layoutMain`), tab IDs, `loadPane` targets and `feedback`/`commands` callbacks remain stable for current graph actions and nested frames. Drag a divider to resize; **Reset layout** restores only panel sizes, while **Reset workspace** reloads application panels and restores the preview connection form.

The opt-in graph pane now loads `webservice/GraphView.jsp` with a collapsible **Graph tools** menu; it preserves the original control IDs and loads the same `GraphView.js` and Fink stylesheet. Its canvas uses pane-owned height instead of the legacy viewport magic constant, while panel 05 remains the scrollable activity/Gremlin-request log. The shared controller now guards delayed canvas loading and cancels pending graph requests on workspace reset, encodes requests, reports graph/value failures in panel 05, prevents duplicate group work and unbounded expansion iteration, preserves zoom when redrawing, disposes replaced vis networks, keeps edge endpoints consistent after removal/filtering, respects the zoom-cluster toggle, and expands either endpoint of a double-clicked edge according to the Children/Parents menu. Edge expansion with Replace current graph keeps both endpoints and the selected relation. These changes affect both the preview and the root shell; their source-level graph contracts have offline behavior tests. The selected-action integration lets internal Show/Table/Venn links load Results/Table/Plot without their `href="#"` fallback navigating to the WAR-root legacy page (the preview's `<base>` made that fallback visible). It also sends object-vertex Fink Portal links to the ZTF or LSST website according to the `objectId` prefix rather than the ZTF API endpoint. These shared graph/stylesheet changes preserve the original action targets and tab callbacks.

GraphView's request log, the preview `feedback` callback and pane-loading status append text rather than interpreting arbitrary callback text as HTML. Legacy context-action HTML and result-tab rendering are not sanitized by this iteration; avoid treating this as an application-wide security review. The shared Venn view uses compact A/B labels on a vertical diagram, puts full classifier names in a separate legend, and shows aligned set/intersection/union counts with consistently rounded percentages. The diagram precedes the statistics when a narrow Plot pane stacks the cards, and the Plot, standalone and popup entry points request versioned CSS/JS so a cached older horizontal renderer does not survive a WAR update. In complete containment it hides coincident in-circle labels and explains the relationship in the legend panel; tiny nonzero fractional counts retain visible precision, while non-finite totals report unavailable data. The B-only count uses B minus intersection (not A minus intersection); zero unions show a dash rather than NaN. The Plot fragment, direct Venn page and correlogram popup share the renderer and responsive styling. The legacy root `GraphView.jsp` still computes its initial `#vis` height with a viewport expression. The preview supplies its expected global `height` and lets the graph pane own the displayed height with flex CSS; a resize observer updates `visheight` and redraws an existing network without changing zoom. The initial load, automatic profile bootstrapping and all backend-driven actions remain owned by the original JSPs and scripts. In particular, this preview does not claim to repair missing backend data or detail-pane behavior.

The graph vertex/edge Table view keeps its original x/y/z/s/k control colors and the same Scatter/Evolution/Sky/Correlogram actions. Expanded properties now have aligned, escaped values and distinct accessible selectors for each expanded row. Scatter plots use a responsive SVG with valid-zero handling, color groups, size encoding, plain-text tooltips and keyboard-accessible point actions. In the opt-in workspace, `workspace.js` routes encoded graph-table Scatter loads to its own `webservice/d3/scatterplot.jsp` and assets, annotating plotted points with their actual selected x/y field names. That renderer displays one `column - value` per line in point notes, omits repeated fields, and removes the list of points below the plot; the original `src/ws/d3` renderer is untouched. For graph Tables with a `time` column, Evolution routes to the same preview renderer with one time series for each selected x and y field (both selections appear together); z sets size, s retains color grouping, and k appears in point details. The `time` field accepts epoch seconds, epoch milliseconds, and ISO/UTC dates; the legacy HBase evolution route remains unchanged because its data contract differs. The graph-table scatter route now transmits JSON through encoded query parameters; the plotting JSP quotes labels and serializes JSON rather than splitting raw text on commas. Correlogram loads with parseable pair data use an opt-in `webservice/d3/correlogram.jsp` renderer with compressed but monotonic circle radii, full-name and full-count hover notes, compact lower-left counts, and Venn-on-click. Malformed legacy payloads are sent to the safe preview renderer as an explicit error rather than to the old inline-script route. The original `src/ws/d3` correlogram is unchanged. The legacy HBase table's plotting route does not supply graph-table `tdata`; it is outside this graph Table iteration and still needs backend-specific integration review.

The four panel titles in the preview carry consistent question-mark controls for Connection, Graph, Analysis, and Activity. Analysis help follows its active Result, Table, Image, Plot, or SkyView tab, including programmatic tab switches. The controls remain in the panel chrome when a pane action replaces its contents; old inline fragment buttons are hidden only in this opt-in view. All eight preview help documents live under `src/webservice/Help-*.html`, based on the original `src/ws/Help-*.html` files, with corrected titles, text, and shared popup styling. Legacy help files are untouched. `node src/test/js/test_webservice_help.js` checks routing, targets, and text structure.

The opt-in SkyView adds a **SkyView** action beside **Table** for object vertices without changing the root stylesheet. Selecting one object plots every object vertex still in the current GraphView (including members of collapsed clusters), deduplicated by object ID; an object removed from the graph is no longer included. The preview-only `webservice/Stylesheet.js` and `skyview-graph.js` retain exact graph object IDs in a sidecar and submit a bounded POST to same-origin `webservice/SkyPositions.jsp`. The proxy batches read-only Elasticsearch `_mget` lookups across ZTF `radec`, LSST `dia_radec`, and (for LSST IDs missing from DIA) `ss_radec`, converting stored longitude back to RA and preserving all Solar System positions. The graph-wide renderer is under `webservice/d3/skyview.*`; the old table Sky route and `src/ws/d3/skyview*` stay untouched. The endpoint allows at most 500 object IDs and 4000 positions per request, returns missing IDs, and fails visibly rather than silently dropping excess points. It does not take hosts or index names from a browser request. For isolated local fixtures only, JVM properties `fink.skyview.ztfEsUrl` and `fink.skyview.lsstEsUrl` can point to loopback fake ES servers. Sample bounded read-only comparisons found one-object ES lookups faster than Fink REST calls, and ES supports batching; these timings are network-dependent and REST returns richer source records, so they are not general API benchmarks.

The preview-only **Cutouts** action beside SkyView opens the existing **Image** tab and builds a three-column contact sheet for every distinct object in the current graph (including clustered objects). Each object's row shows the latest Science, Template, and Difference PNG from Fink Portal. ZTF cutouts use the object ID directly; LSST cutouts require a diaSourceId, resolved from the most recent source for each diaObject via a bounded, read-only same-origin `webservice/CutoutSource.jsp` lookup. Image URLs then point directly to the respective HTTPS Fink Portal cutout endpoint. At most 30 objects (90 PNGs) can be loaded per action; missing sources/stamps are shown as errors in their cells. Source requests are concurrency-limited and cancelled when the Image pane changes or the workspace resets. The root stylesheet and `src/ws/**` remain unchanged. Test with `node src/test/js/test_webservice_cutouts_graph.js`; a browser smoke check can use `?profile=null` with a synthetic graph snapshot rather than connecting to a production graph.

The preview SkyView iframe fills the available Analysis pane height instead of inheriting a 360px intrinsic height. Its map resizes within the pane's current width and height (including divider/window resizing); zoom and PNG/SVG download buttons remain visible. The original Celestial settings remain available under **Map settings**, and the long coordinate list is collapsed under **Plotted object coordinates** until needed, so neither causes a second page scrollbar.

SkyView labels each plotted point with its object ID in small type, shifting the label to the left near the canvas edge; hovering the marker shows its full ID in a light popup. ZTF points and labels use orange and LSST points and labels blue, with a matching compact legend. Marker hit-testing follows the canvas projection after zoom and resize, while the popup displays IDs as plain text rather than HTML.
