# FinkBrowser web application

`src/webservice/` is the single source tree for the web-facing files in `FinkBrowser.war`. Build it from `ant/` with `ant war` using the usual local Ant properties and Java dependencies. The build stages token-substituted `index.jsp`, `Top.jsp`, `Apps.html`, `Servers.jsp`, and `Graphs.jsp`, then packages the rest of this directory at the WAR root, plus compiled libraries and vendored assets from `extlib/ws`. It does not build `Lomikel.war` or package `src/ws/**`. Files retained under `src/ws/` are legacy or independently used; review them separately before removal.

The default entry is `http://localhost:8888/FinkBrowser/index.jsp` (subject to the configured Jetty port), with **no query parameters required**. Without `profile`, the shell uses the existing `null` profile: it starts without a production graph connection. An explicit, configured `?profile=...` still selects that profile and can reach a live backend. Do not use a production profile just to test the layout. `ant start-FinkBrowser` builds and runs the WAR; `ant war` itself does not deploy it. The application metadata in the WAR is `FinkBrowser`.

Three standalone applications are packaged at `/FinkBrowser/AlertsView/index.html`, `/FinkBrowser/LightCurveView/index.html`, and `/FinkBrowser/ClassificationView/index.html`. Their header links open new tabs. AlertsView's local Ant start target runs the JSP-capable FinkBrowser WAR (its data proxy cannot be served by a static Python server); the other two can also be served independently with their local static-server targets. The ClassificationView graph helper and D3 file are regular files inside its source directory, not symlinks to sources outside it.

## Workspace contracts

The five-panel shell keeps the existing `layout`, `layoutLeft`, and `layoutMain` layout names, `resultTab`, `tableTab`, `imageTab`, `plotTab`, and `skyviewTab` IDs, and the `feedback`/`commands` callbacks used by graph actions and nested Plot frames. The header keeps `id="mini"` for graph initialization, while the connection pane keeps `id="top"`. **Reset workspace** clears graph/results; **Reset layout** restores panel sizes without clearing data. Each panel has contextual help. A graph Table retains its x/y/z/s/k controls and original button colors.

Object actions include survey-aware portal links, graph-wide SkyView and Cutouts, per-object LightCurve, and selected-object Table/Plot actions. Mixed-server graph tables retain the originating server for each vertex. The analysis plots include responsive Scatter, Evolution, Correlogram and Venn views; SkyView, LightCurve and Correlogram fit their host panes. Survey-specific object icons, map markers and cutout backgrounds distinguish ZTF and LSST. The graph stylesheet returns bare icon filenames because `GraphView.js` adds the `images/` prefix. Where a Plot or image pane is replaced or the workspace resets, pending preview work is invalidated. Keep URL encoding, bounded lookups and HTML escaping when extending these routes; this is not an application-wide legacy-HTML security audit.

The `SkyPositions.jsp` and `CutoutSource.jsp` proxies use fixed, read-only Elasticsearch hosts, with explicit per-request limits. `LightCurveData.jsp` uses fixed Fink REST hosts with bounded responses; it plots ZTF PSF magnitudes and LSST science-flux AB magnitudes in the returned bands. Source endpoints and the three standalone apps may require network access; a successful offline shell smoke test is not a full live-data integration test.

## Verification

From the repository root, run `python -m unittest discover -s src/test/python -p 'test_webservice*.py' -q`, every `src/test/js/test_*.js` file with Node, and `node --test` for each `src/webservice/*/tests/*.cjs` suite. Build first so the Python archive assertions inspect the latest `lib/FinkBrowser.war`. Verify the archive has unique entries, root JSPs, all three standalone apps and their assets, and no old `/webservice/index.jsp` alias. In an isolated Jetty Runner on `127.0.0.1`, visit `/FinkBrowser/index.jsp` without arguments; confirm that the shell and graph pane appear without a backend query, scripts/images load without HTTP errors, and the three standalone URLs respond. For interactive graph tests use `profile=null` with synthetic fixtures, not a configured production graph. Backend-dependent graph actions require a separate, explicitly scoped integration test.
