# FinkBrowser workspace preview

This opt-in iteration refines the workspace shell, the header and panel 02 without changing the backend logic of the panels. The existing root `index.jsp` remains the default welcome page. The new shell is available at `/FinkBrowser/webservice/index.jsp` after `ant war`; use `?profile=null` to inspect it without an automatic graph query, or the same configured profile query string used by the existing UI. Do not run a configured profile against production merely to test layout.

Build from `ant/` with `ant war` using the usual local Ant properties and dependencies. `ant start-FinkBrowser` serves the resulting `lib/FinkBrowser.war` at the configured port, but starts a service that may connect to the configured backends. `ant war` does not deploy it; neither the `deploy*` targets nor a remote server are needed to preview the shell. For an isolated local test, run Jetty Runner bound to `127.0.0.1` on a spare port using the built WAR.

The new JSP is packaged under `webservice/`, but its `<base>` points at the WAR root so existing JS, CSS, detail fragments and relative action URLs remain unchanged. It statically includes the Fink `Init.jsp`. Panel 01's information and Reset workspace control are now in the top header: the `LomikelOverlap.png` icon sits beside a linked application name, and Version opens a light dialog containing the build metadata. The header keeps `id="mini"` for the existing graph initialization contract; the preview-only `TopMini.jsp` is no longer loaded or packaged. Panels 02 and 05 start at roughly half their former height and remain resizable and scrollable. Panel 02 still loads preview-only `webservice/Top.jsp`, preserving the original server/graph/command controls, action IDs, Gremlin callbacks and dynamic `#commands` target; its initial command is substituted by the WAR build. The legacy pages remain unchanged. Other panels still load their root fragments. The w2ui layout names (`layout`, `layoutLeft`, `layoutMain`), tab IDs, `loadPane` targets and `feedback`/`commands` callbacks remain stable for current graph actions and nested frames. Drag a divider to resize; **Reset layout** restores only panel sizes, while **Reset workspace** reloads application panels and restores the preview connection form.

The opt-in graph pane now loads `webservice/GraphView.jsp` with a collapsible **Graph tools** menu; it preserves the original control IDs and loads the same `GraphView.js` and Fink stylesheet. Its canvas uses pane-owned height instead of the legacy viewport magic constant, while panel 05 remains the scrollable activity/Gremlin-request log. The shared controller now guards delayed canvas loading and cancels pending graph requests on workspace reset, encodes requests, reports graph/value failures in panel 05, prevents duplicate group work and unbounded expansion iteration, preserves zoom when redrawing, disposes replaced vis networks, keeps edge endpoints consistent after removal/filtering, respects the zoom-cluster toggle, and expands either endpoint of a double-clicked edge according to the Children/Parents menu. Edge expansion with Replace current graph keeps both endpoints and the selected relation. These changes affect both the preview and the root shell; their source-level graph contracts have offline behavior tests. The selected-action integration lets internal Show/Table/Venn links load Results/Table/Plot without their `href="#"` fallback navigating to the WAR-root legacy page (the preview's `<base>` made that fallback visible). It also sends object-vertex Fink Portal links to the ZTF or LSST website according to the `objectId` prefix rather than the ZTF API endpoint. These shared graph/stylesheet changes preserve the original action targets and tab callbacks.

GraphView's request log, the preview `feedback` callback and pane-loading status append text rather than interpreting arbitrary callback text as HTML. Legacy context-action HTML and result-tab rendering are not sanitized by this iteration; avoid treating this as an application-wide security review. The shared Venn view uses compact A/B labels on a vertical diagram, puts full classifier names in a separate legend, and shows aligned set/intersection/union counts with consistently rounded percentages. The diagram precedes the statistics when a narrow Plot pane stacks the cards, and the Plot, standalone and popup entry points request versioned CSS/JS so a cached older horizontal renderer does not survive a WAR update. In complete containment it hides coincident in-circle labels and explains the relationship in the legend panel; tiny nonzero fractional counts retain visible precision, while non-finite totals report unavailable data. The B-only count uses B minus intersection (not A minus intersection); zero unions show a dash rather than NaN. The Plot fragment, direct Venn page and correlogram popup share the renderer and responsive styling. The legacy root `GraphView.jsp` still computes its initial `#vis` height with a viewport expression. The preview supplies its expected global `height` and lets the graph pane own the displayed height with flex CSS; a resize observer updates `visheight` and redraws an existing network without changing zoom. The initial load, automatic profile bootstrapping and all backend-driven actions remain owned by the original JSPs and scripts. In particular, this preview does not claim to repair missing backend data or detail-pane behavior.

The graph vertex/edge Table view keeps its original x/y/z/s/k control colors and the same Scatter/Evolution/Sky/Correlogram actions. Expanded properties now have aligned, escaped values and distinct accessible selectors for each expanded row. Scatter plots use a responsive SVG with valid-zero handling, color groups, size encoding, plain-text tooltips and keyboard-accessible point actions. In the opt-in workspace, `workspace.js` routes encoded graph-table Scatter loads to its own `webservice/d3/scatterplot.jsp` and assets, annotating plotted points with their actual selected x/y field names. That renderer displays one `column - value` per line in point notes, omits repeated fields, and removes the list of points below the plot; the original `src/ws/d3` renderer is untouched. Evolution and legacy HBase still use the old route because their data contracts differ. The graph-table scatter route now transmits JSON through encoded query parameters; the plotting JSP quotes labels and serializes JSON rather than splitting raw text on commas. Evolution and Correlogram caller behavior remains separate. The legacy HBase table's plotting route does not supply graph-table `tdata`; it is outside this graph Table iteration and still needs backend-specific integration review.
